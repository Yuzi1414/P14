# 线上账号持久化配置（Render 免费版 + Supabase）

## 为什么需要这一步

线上部署在 Render 免费实例上，容器磁盘是**临时的**：

- 15 分钟无人访问 → 自动休眠，下次访问唤醒时磁盘重置
- 每次 `git push` 触发重新部署 → 磁盘重置

账号原本存在 `runtime/users.json`，这个文件在重置中消失，于是：

| 现象 | 原因 |
|---|---|
| 注册的账号第二天登录不上 | `users.json` 被清空，账号随之消失 |
| 管理员密码回到 `admin123` | 文件不存在时 `_ensure_admin()` 用硬编码密码重建 |
| 明明没退出却被要求重新登录 | `runtime/.session_secret` 重新随机生成，URL 里的登录令牌签名失效 |

**免费版不支持 Persistent Disk**，所以不能用「挂盘」解决。本方案把账号挪到 Supabase 免费 Postgres，容器怎么重启都不影响。

---

## 一、Supabase 侧（约 5 分钟）

1. 打开 https://supabase.com 注册（可用 GitHub 登录），点 **New project**
   - Name：`p14-reconcile`
   - Database Password：自己设一个强密码，**记下来**（后续连接串会用到）
   - Region：选 `Southeast Asia (Singapore)`，离国内最近
   - Plan：Free

2. 项目创建完成后（约 2 分钟初始化），进入左侧 **SQL Editor** → **New query**

3. 粘贴并运行 `docs/supabase_setup.sql` 的全文，点 **Run**。执行成功应看到：
   ```
   Success. No rows returned
   ```

4. 左侧 **Table Editor**，确认能看到 `app_users` 表（此时为空）。

5. 左侧 **Project Settings**（齿轮图标）→ **API Keys**，记下两个值：
   - **Project URL** —— 形如 `https://abcdefghijkl.supabase.co`
   - **service_role secret** —— 形如 `eyJhbGciOi...`，很长
     ⚠️ 这是**最高权限**的 key，只能填进 Render 的环境变量，**绝不能**写进代码或提交到 Git。

---

## 二、Render 侧（约 3 分钟）

进入 https://dashboard.render.com → 选中 `p14-reconcile` 服务 → 左侧 **Environment** → **Add Environment Variable**，添加三条：

| Key | Value | 说明 |
|---|---|---|
| `SUPABASE_URL` | 你的 Project URL | 例如 `https://abcdefghijkl.supabase.co` |
| `SUPABASE_KEY` | 你的 service_role secret | 长串 eyJ... 开头 |
| `SESSION_SECRET` | 随机 64 位十六进制 | 让登录令牌跨重启有效，见下方生成方式 |

`SESSION_SECRET` 生成方法，任选其一：

```bash
# Linux / macOS / Git Bash
openssl rand -hex 32

# Python
python -c "import secrets; print(secrets.token_hex(32))"
```

保存后 Render 会自动重新部署（约 2–3 分钟）。

---

## 三、验证

1. 打开 https://p14-reconcile.onrender.com/
2. 展开左侧边栏，底部应显示：
   ```
   账户存储：Supabase 云端
   ```
   - 显示「本地文件」→ 环境变量没生效，回 Render 检查拼写，注意不要有空格
3. 注册一个新账号 → 退出 → 重新登录，能登进去即成功
4. 去 Supabase **Table Editor → app_users**，应能看到刚注册的用户名

**最终验证（关键）**：在 Render 控制台手动点 **Manual Deploy → Restart service**，等重启完成后再登录一次。账号还在，就说明彻底修好了。

## 四、本地开发不受影响

本地没有设置这两个环境变量时，`build_auth()` 自动回退到 `runtime/users.json`，行为与改动前完全一致：

```python
from reconcile.auth import build_auth
auth = build_auth(ROOT / "runtime" / "users.json")
# 有 SUPABASE_URL + SUPABASE_KEY → SupabaseAuth
# 否则                          → AuthStore（本地 JSON）
```

想在本地也连 Supabase 测试，可以临时设置环境变量：

```bash
# Git Bash
export SUPABASE_URL="https://xxx.supabase.co"
export SUPABASE_KEY="eyJ..."
.venv/Scripts/python.exe -m streamlit run app.py
```
