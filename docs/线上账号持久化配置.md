# 线上数据持久化配置（Render 免费版 + Supabase）

## 为什么需要这一步

线上部署在 Render 免费实例上，容器磁盘是**临时的**：

- 15 分钟无人访问 → 自动休眠，下次访问唤醒时磁盘重置
- 每次 `git push` 触发重新部署 → 磁盘重置

原本账户和任务数据都存在容器里，重置中一起消失，于是：

| 现象 | 原因 |
|---|---|
| 注册的账号第二天登录不上 | `runtime/users.json` 被清空，账号随之消失 |
| 管理员密码回到 `admin123` | 文件不存在时 `_ensure_admin()` 用硬编码密码重建 |
| 明明没退出却被要求重新登录 | `runtime/.session_secret` 重新生成，URL 里的登录令牌签名失效 |
| 导入的对账数据第二天不见了 | `runtime/tasks/*.db` 被清空 |

**免费版不支持 Persistent Disk**，所以不能用「挂盘」解决。本方案把**账户**和**任务数据**都挪到 Supabase 免费 Postgres，容器怎么重启都不影响。

---

## 一、Supabase 侧（约 5 分钟）

1. 打开 https://supabase.com 注册（可用 GitHub 登录），点 **New project**
   - Name：`p14-reconcile`
   - Database Password：自己设一个强密码，**记下来**
   - Region：选 `Southeast Asia (Singapore)`，离国内最近
   - Plan：Free

2. 项目创建完成后（约 2 分钟初始化），进入左侧 **SQL Editor** → **New query**

3. 粘贴并运行 `docs/supabase_setup.sql` 的全文，点 **Run**。成功应看到一张两行的统计表：
   ```
   app_users | 0
   app_tasks | 0
   ```
   如果之前已经建过 `app_users`，脚本不会破坏它（都是 `if not exists`）。

4. 左侧 **Table Editor**，确认能看到 `app_users` 和 `app_tasks` 两张表。

5. 左侧 **Project Settings**（齿轮图标）→ **API Keys**，记下两个值：
   - **Project URL** —— 形如 `https://abcdefghijkl.supabase.co`
   - **service_role secret** —— 形如 `eyJhbGciOi...`，很长
     ⚠️ 这是**最高权限**的 key，只能填进 Render 的环境变量，**绝不能**写进代码或提交到 Git。

---

## 二、Render 侧（约 3 分钟）

进入 https://dashboard.render.com → 选中 `p14-reconcile` 服务 → 左侧 **Environment** → **Add Environment Variable**，添加三条：

| Key | Value | 说明 |
|---|---|---|
| `SUPABASE_URL` | 你的 Project URL | 例如 `https://abcdefghijkl.supabase.co` |
| `SUPABASE_KEY` | 你的 service_role secret | 长串 `eyJ...` 开头 |
| `SESSION_SECRET` | 随机 64 位十六进制 | 让登录令牌跨重启有效 |

`SESSION_SECRET` 生成方法，任选其一：

```bash
# Linux / macOS / Git Bash
openssl rand -hex 32

# Python
python -c "import secrets; print(secrets.token_hex(32))"
```

保存后 Render 会自动重新部署（约 2–3 分钟）。

---

## 三、验证

1. 打开 https://p14-reconcile.onrender.com/
2. 展开左侧边栏，底部应显示：
   ```
   账户存储：Supabase 云端
   任务存储：Supabase 云端
   ```
   - 任一行显示「本地文件 / 本机文件」→ 环境变量没生效，回 Render 检查拼写，注意不要有空格
3. 注册账号 → 导入一份对账数据 → **手动点 Restart service**
4. 重启完成后再登录：账号能进、对账数据还在，就彻底修好了
5. 去 Supabase **Table Editor** 看两张表都有数据落库

## 四、本地开发不受影响

本地没有设置这两个环境变量时，自动回退到本地文件，行为与改动前完全一致：

```python
from reconcile.auth import build_auth
from reconcile.storage import build_store

auth  = build_auth(ROOT / "runtime" / "users.json")
store = build_store(task_db_path, task_key)
# 有 SUPABASE_URL + SUPABASE_KEY → SupabaseAuth / SupabaseStore
# 否则                          → AuthStore / Store（本地 JSON + SQLite）
```

想在本地也连 Supabase 测试，可以临时设置环境变量：

```bash
export SUPABASE_URL="https://xxx.supabase.co"
export SUPABASE_KEY="eyJ..."
.venv/Scripts/python.exe -m streamlit run app.py
```

## 五、数据是这么存的

**app_users** —— 一行一个账号

| 列 | 说明 |
|---|---|
| `username` | 主键，统一转小写 |
| `password_hash` / `salt` | PBKDF2-HMAC-SHA256，20 万次迭代，从不存明文 |
| `role` / `status` | `admin` / `用户`；`active` |
| `created_at` | 创建时间 |
| `last_active_at` | 最近一次业务操作时间（导入 / 建账 / 复核等），权限页「最近操作时间」列显示 |

**app_tasks** —— 一行 = 一个账号在一台设备上的工作台

| 列 | 说明 |
|---|---|
| `task_key` | 主键，`{用户名slug}_{用户名hash}_{设备标识}` |
| `schema_version` | 当前为 1，版本不符会拒绝读取而不是误解析 |
| `payload` | 整份任务 JSON（记录、配对、分组、复核意见、AI 日志） |
| `updated_at` | 最后保存时间 |

按「账号 + 设备」隔离的设计没变：换台电脑登录拿到新的设备标识，看到的是空白工作台，需要走「发布到云端共享 / 从云端共享载入」。

## 六、免费额度

| 项目 | Free 版额度 |
|---|---|
| 数据库存储 | 500 MB |
| 行数限制 | 无 |
| 项目暂停 | 7 天无请求会暂停，登录控制台点 Restore 即可恢复 |
| 备份 | 每日自动备份，保留 7 天 |

一次对账任务约 100–300 KB JSON（取决于导入行数），500 MB 可存约 2000 份完整任务，够用很久。

## 七、注意事项

- **`service_role` key 泄露 = 数据库全开**。只放 Render 环境变量，别贴群里、别提交 Git。
- **免费版项目 7 天无请求会暂停**。长期不用后第一次打开可能报错，去 Supabase 控制台点 Restore，等 1 分钟。
- **RLS 已开启且不授任何策略**：浏览器端拿 anon key 读不到任何数据，只有服务端用 service_role 能访问。
- 账户和任务都上云后，`runtime/` 目录在线上不再有实际用途，本地开发还是用它。
